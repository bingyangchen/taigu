# 0013 沒有網路時的畫面

## 目標

裝置沒有網路，或開啟 Taigu 時連不上後端，畫面會清楚告訴使用者，不再顯示沒有資料的頁面或一直轉圈。開啟時連不上，就停在開啟時的讀取畫面，把轉圈換成「沒有網路連線」或「無法連上 Taigu」，讓使用者重試；使用中途沒有網路時，頁面照常可以閱讀與操作，畫面上多一個不改變版面的提示，說明連上網路前資料不會更新，恢復網路後提示消失，前端隨即更新畫面上的行情。

## 範圍

- 要做：
  - ACCT-R3 裡要登入才能使用的頁面（前台與後台），開啟時與從不需要登入的頁面換過來時，沒有網路或連不上後端的讀取畫面。
  - 這些頁面在使用中途沒有網路時的提示，以及恢復網路後更新行情。
  - 把各 spec 裡「裝置沒有連上網路」時操作失敗的情境，改成「前端連不上後端」，讓這些情境不必再考慮 ACCT-R18 的提示；使用中途沒有網路時送出失敗的情況，由 ACCT-R18.19 檢查。
  - 修改隱私權政策裡「以供離線讀取」的說法。
- 刻意不做的事：
  - 不讓 Taigu 離線可用：開啟時沒有網路，不畫出頁面。
  - 使用中途不擋住頁面，也不在頁面裡插入會推動版面的橫幅（見「決策」）。
  - 使用中途連不上後端、但瀏覽器回報有網路時，不顯示提示（見「決策」）。
  - 不移除 service worker 的 API cache 與 IndexedDB（見「決策」）。
  - 歡迎頁、登入頁、法律頁面與 404 頁面不套用。

## 設計稿

- `design/offline-screen.html`：開啟時的讀取畫面有讀取中、沒有網路、連不上後端與重試中四種狀態，沿用 `LoadingScreen` 的畫面與 logo，把轉圈的位置換成狀態的文字與「重試」按鈕，前台的窄版與寬版、後台都用同一個畫面。
- 同一份設計稿畫出使用中途沒有網路時的提示，樣式跟 toast 一致，位置依以下規則決定：
  - 前台的寬版與後台：浮在右下角，跟 toast 同一個位置。
  - 前台窄版有底部導覽列的頁面：放在底部導覽列上方、加號按鈕的左側，因為窄版的 toast 在頂端，會蓋住頁首的按鈕。
  - 前台窄版沒有底部導覽列的頁面（編輯頁、設定頁）：放在底部，有底部按鈕時放在按鈕上方。
- 設計稿也畫出提示與錯誤 toast 同時出現、寬版開著編輯器視窗，以及頁面自己的讀取畫面顯示時的提示。

### account.md

#### 開頭的說明

這份 spec 的範圍加上沒有網路或連不上後端時的畫面。以「使用者要先用 Google 帳號登入 Taigu」開始的那一段改成：

使用者要先用 Google 帳號登入 Taigu，才能記帳與使用其他功能。這份 spec 寫的是登入、登入狀態維持多久與怎麼結束、未登入時開啟頁面會被導去哪裡、沒有網路或連不上後端時要登入才能使用的頁面顯示什麼，以及設定頁（`/settings`）的總覽與兩項帳號設定（修改名字與頭像、更換綁定的 Google 帳號）。資料的匯出見 REC-R20，方案與付款寫在 [billing.md](billing.md)。

開頭的其他部分不變。

#### ACCT-R17 清除瀏覽器保存的帳號資料

瀏覽器保存的現金股利紀錄不再寫成離線讀取用的資料，清除的範圍不變；情境的結果改成檢查瀏覽器裡存的資料，因為做了 ACCT-R18 之後，沒有網路時前端不會畫出頁面，無法從畫面看出舊資料有沒有清除。規則改成：

主動登出（見 ACCT-R7）或確認登入已失效（見 ACCT-R5）時，前端清除這個瀏覽器保存的帳號資料，包括交易紀錄、同步進度、現金股利紀錄、買賣計畫、自選股、個股筆記、手續費折讓、最近點選過的股票，以及之前記住的登入後返回網址。登入失效後，前端依 ACCT-R5 在清除完成後另行記住這次開啟的網址。

修改以下情境，ACCT-R17 的其他部分不變：

- ACCT-R17.1 主動登出後換另一個帳號登入
  - 前提：帳號 A 在瀏覽器中留下上述各種資料。
  - 動作：帳號 A 主動登出，接著從登入頁登入帳號 B。
  - 結果：前端在登入帳號 B 前已清除帳號 A 的上述資料；使用者登入帳號 B 後，瀏覽器的 IndexedDB 與 service worker cache 裡沒有帳號 A 的資料，畫面上也看不到帳號 A 最近點選過的股票，前端也不使用帳號 A 的舊返回網址。
- ACCT-R17.2 登入失效後換另一個帳號登入
  - 前提：帳號 A 在瀏覽器中留下上述各種資料，之後登入到期。
  - 動作：開啟 `/records?sid=2330` 觸發登入失效處理，再於原分頁未滿 30 分鐘時登入帳號 B。
  - 結果：前端在登入帳號 B 前已清除帳號 A 的上述資料；使用者登入帳號 B 後，瀏覽器的 IndexedDB 與 service worker cache 裡沒有帳號 A 的資料，畫面上也看不到帳號 A 最近點選過的股票，畫面依 ACCT-R3 返回這次開啟的 `/records?sid=2330`。

設計理由不再寫成離線讀取用的資料，理由本身不變。設計理由改成：

> 設計理由：登出時刪除瀏覽器保存的帳號資料，是為了讓同一個瀏覽器之後登入的人看不到前一個帳號的資料。

#### ACCT-R18 沒有網路或連不上後端時的畫面

新增這條需求，放在 ACCT-R17 之後：

### ACCT-R18 沒有網路或連不上後端時的畫面

這條需求適用於 ACCT-R3 裡要登入才能使用的頁面。下面的詞這樣定義：

- 瀏覽器的回報：網路狀態改變時瀏覽器發出的通知，以及開啟或重新整理頁面、頁面畫出來、切回 Taigu（「切回」的意思見 USAGE-R1）或從 bfcache 還原頁面時，瀏覽器當下回報的網路狀態。
- 沒有網路：瀏覽器的回報是裝置沒有連上網路。
- 恢復網路：瀏覽器的回報從沒有網路變成有網路。
- 連不上後端：瀏覽器的回報是有網路，但前端送到後端的 request 因連線失敗結束，例如後端的網域查不到，或連線被拒絕。
- 讀取畫面：只有 Taigu 的 logo、還沒有頁面內容的畫面，例如開啟 Taigu 時看到的畫面；讀取中會顯示轉圈圖示。

頁面畫出來之前的規則如下。開啟或重新整理這些頁面，或在 Taigu 裡從不需要登入的頁面換到這些頁面時，前端先讀取帳號資料確認登入狀態，才畫出頁面。前端為了讀到帳號資料所做的一段讀取，稱為一次「嘗試」：從送出第一個 request 起，到讀到結果、這次嘗試結束或滿 10 秒為止，中間自動再送的 request 都算同一次嘗試。

頁面畫出來之前，前端在以下時候自動開始一次嘗試：

- 有網路時開啟或重新整理頁面。
- 有網路時從不需要登入的頁面換過來。
- 恢復網路時。

使用者點「重試」時，不論是否沒有網路，前端都開始一次嘗試。

> 設計理由：沒有網路時也提供「重試」，而且重試時不看瀏覽器回報的網路狀態，因為瀏覽器可能誤報沒有網路，安裝成 PWA 時又沒有重新整理的按鈕，沒有「重試」的話使用者只能強制關閉 Taigu。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

Request 因連線失敗結束時：

- 自動開始的嘗試：前端隔 1 秒再送，直到讀到結果或滿 10 秒，所以一次嘗試最多送出約 10 個 request。
- 點「重試」開始的嘗試：前端不再送，這次嘗試就此結束。

> 設計理由：自動開始的嘗試在 10 秒內遇到連線失敗時再試，因為解鎖手機或剛恢復網路時，瀏覽器常常比網路真的通了更早回報有網路，第一個 request 失敗就顯示「無法連上 Taigu」的話，使用者會常常得自己點「重試」；代價是後端真的停機時，使用者要看 10 秒轉圈的讀取畫面才看到原因。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

畫面依以下規則決定：

- 任何一次嘗試讀到帳號資料：前端畫出頁面。滿 10 秒時前端不中止還在進行的 request，所以畫面已經換成「無法連上 Taigu」之後，那個 request 才讀到帳號資料的話，前端也直接畫出頁面，使用者不用點「重試」。
- 任何一次嘗試確認未登入或登入已失效：依 ACCT-R3 與 ACCT-R5。
- 沒有網路：讀取畫面的轉圈換成「沒有網路連線」與「重試」按鈕，不論原本顯示什麼、嘗試是否進行中。
- 有網路，最新一次嘗試還在進行：
  - 開啟或重新整理頁面時，以及恢復網路時自動開始的嘗試：畫面是讀取畫面，顯示轉圈。
  - 從不需要登入的頁面換過來時自動開始的嘗試：畫面停在原本的頁面。
  - 點「重試」開始的嘗試：畫面不變。
- 有網路，最新一次嘗試沒有讀到帳號資料就結束，或滿 10 秒還沒讀到：讀取畫面的轉圈換成「無法連上 Taigu」與「重試」按鈕。沒有讀到帳號資料就結束的情況有：
  - 後端回了錯誤，但沒有確認未登入或登入已失效。
  - 點「重試」開始的嘗試連線失敗。
- 較早的嘗試失敗或滿 10 秒：不改變畫面。

> 設計理由：開啟時連不上後端，畫面停在讀取畫面，前端不畫出頁面讓使用者看瀏覽器裡存下的資料，因為 Taigu 顯示的價格與損益是投資判斷的依據，這時畫面上沒有任何剛取得的數字，頁面上的提示再明顯，也會有人把舊的數字當成目前的數字。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

「重試」只有在點「重試」開始的嘗試還在進行、還沒滿 10 秒時不能點。

頁面畫出來之後，前端依以下規則處理：

- 前端不再自動開始嘗試，也不再因為這條需求顯示讀取畫面。
- 前端在背景重新讀取帳號資料（見 architecture.md 的「頁面使用 Loader 讀到的帳號資料」）不算嘗試，讀取失敗時不改變畫面。
- 頁面自己讀取資料時的畫面，例如儀表板讀取交易紀錄時的讀取畫面，依各能力的 spec。

使用中途沒有網路時的提示依以下規則顯示：

- 瀏覽器持續回報沒有網路滿 3 秒時，畫面才顯示「沒有網路連線」的提示，寫明連上網路前畫面上的資料不會更新。瀏覽器在頁面畫出來時、使用者切回 Taigu 時或從 bfcache 還原頁面時才回報沒有網路的話，3 秒從那時起算。

  > 設計理由：沒有網路滿 3 秒才顯示提示，是為了讓訊號短暫中斷時畫面不閃動。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

- 提示浮在頁面上，不改變頁面的版面，也不蓋住導覽、加號按鈕、底部按鈕與使用者正在輸入的欄位。

  > 設計理由：使用中途沒有網路時只顯示提示，不像開啟時那樣擋住整個畫面，因為畫面上的資料在斷線前是最新的，使用者仍能閱讀；擋住畫面的話，使用者就看不到正在看的內容，在隧道或電梯這種反覆斷線的地方，畫面還會反覆被擋住。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

- 視窗或底部選單開著時，提示在視窗與底部選單下面；頁面自己的讀取畫面顯示時，提示在讀取畫面上面，讓使用者看得到。
- 提示顯示時，使用者照常閱讀與操作頁面，各操作失敗時的畫面依各能力的 spec。
- 連不上後端時，畫面不顯示提示。

  > 設計理由：連不上後端時不顯示提示，因為瀏覽器回報有網路時，單一 request 失敗不能證明前端連不上後端，依失敗次數或時間猜測會誤判，而各能力的 spec 已經規定操作失敗與更新失敗時的畫面。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

恢復網路時，不論提示是否出現過，前端依以下規則處理：

- 提示不再顯示。
- 2 秒後，前端重新抓 MKT-R11 與 MKT-R12 規定目前頁面要定時重新抓的行情，不等下一次間隔，並從這時重新計算間隔。這次抓取成功或失敗時的畫面，跟定時重新抓的時候一樣，依各能力的 spec。

  > 設計理由：恢復網路後等 2 秒才重新抓行情，因為瀏覽器常比網路真的通了更早回報有網路，前端立刻抓的話容易失敗，畫面就會出現各頁的更新失敗提示。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

- ACCT-R18.1 沒有網路時開啟
  - 前提：使用者已經登入，瀏覽器回報沒有網路。
  - 動作：開啟儀表板（`/`）。
  - 結果：畫面顯示「沒有網路連線」與「重試」按鈕，沒有儀表板的內容。
- ACCT-R18.2 恢復網路後接著開啟
  - 前提：ACCT-R18.1 的結果。
  - 動作：瀏覽器回報恢復網路，使用者不點任何按鈕。
  - 結果：恢復網路後，畫面先顯示轉圈的讀取畫面，前端讀到帳號資料後，畫面顯示儀表板。
- ACCT-R18.3 開啟時連不上後端
  - 前提：使用者已經登入，瀏覽器回報有網路，但前端送到後端的 request 都因連線失敗結束。
  - 動作：開啟歷史紀錄頁（`/records`）。
  - 結果：前端開始讀取帳號資料後的前 10 秒，畫面是轉圈的讀取畫面；第 10 秒起畫面顯示「無法連上 Taigu」與「重試」按鈕，沒有歷史紀錄頁的內容。
- ACCT-R18.4 重試成功
  - 前提：ACCT-R18.3 的結果，之後前端可以連上後端。
  - 動作：點「重試」。
  - 結果：畫面顯示歷史紀錄頁。
- ACCT-R18.5 後端回錯誤
  - 前提：使用者已經登入，前端讀取帳號資料時，後端回 500。
  - 動作：開啟儀表板（`/`）。
  - 結果：後端回應之後，不等 10 秒，畫面就顯示「無法連上 Taigu」與「重試」按鈕，沒有儀表板的內容。
- ACCT-R18.6 後端 10 秒內沒有回應
  - 前提：使用者已經登入，前端開始讀取帳號資料之後 15 秒，後端才回應帳號資料。
  - 動作：開啟儀表板（`/`），不點任何按鈕，等待 15 秒。
  - 結果：開始讀取後第 10 秒，畫面顯示「無法連上 Taigu」與「重試」按鈕；第 15 秒後端回應之後，畫面顯示儀表板。
- ACCT-R18.7 剛恢復網路時連線失敗
  - 前提：ACCT-R18.1 的結果。
  - 動作：瀏覽器回報恢復網路，前端送出的第一個 request 因連線失敗結束，恢復網路後第 4 秒，前端讀到帳號資料；使用者不點任何按鈕。
  - 結果：恢復網路之後畫面一直是轉圈的讀取畫面，沒有出現「無法連上 Taigu」，前端讀到帳號資料後，畫面顯示儀表板。
- ACCT-R18.8 重試之後仍然沒有回應
  - 前提：ACCT-R18.3 的結果，前端送到後端的 request 一直沒有回應。
  - 動作：點「重試」，等待 10 秒。
  - 結果：點了之後到第 10 秒之前，畫面仍是「無法連上 Taigu」，「重試」不能再點；第 10 秒起「重試」可以再點。
- ACCT-R18.9 沒有網路時重試失敗
  - 前提：ACCT-R18.1 的結果，前端送到後端的 request 都因連線失敗結束，瀏覽器仍回報沒有網路。
  - 動作：點「重試」。
  - 結果：畫面仍是「沒有網路連線」與「重試」按鈕，沒有換成「無法連上 Taigu」。
- ACCT-R18.10 瀏覽器誤報沒有網路
  - 前提：使用者已經登入，前端連得上後端，但瀏覽器回報沒有網路，而且之後一直沒有回報恢復網路。
  - 動作：開啟儀表板（`/`），點「重試」。
  - 結果：開啟時畫面顯示「沒有網路連線」與「重試」按鈕；點了之後畫面顯示儀表板，3 秒後畫面出現「沒有網路連線」的提示。
- ACCT-R18.11 讀取帳號資料時斷線

### architecture.md

#### 開啟要登入才能使用的頁面時確認登入狀態

沒有網路或讀取帳號資料失敗時不再照常畫出頁面。以「整頁載入時」開始的那一項改成：

- 整頁載入時，例如開啟 Taigu 或重新整理頁面，畫面顯示 `LoadingScreen`，沒有網路或連不上後端時依 ACCT-R18 顯示。之後換成頁面自己顯示的 `LoadingScreen` 時，例如儀表板讀取交易紀錄時，前端讓 `LoadingScreen` 的動畫從原本的進度接著播放。

以「從登入頁、歡迎頁這類不需要登入的頁面換過來時」開始的那一項改成：

- 從登入頁、歡迎頁這類不需要登入的頁面換過來時，畫面停在原本的頁面，沒有網路或連不上後端時依 ACCT-R18 換成讀取畫面。

以「其他失敗時，前端照常畫出頁面」開始的那一項改成：

- 其他失敗時，畫面依 ACCT-R18 顯示，不畫出頁面。前端無法開始讀取帳號資料時，例如 service worker 沒有確認支援帳號資料隔離（見「Service Worker 的帳號資料隔離」），畫面跟讀取失敗時一樣依 ACCT-R18 顯示，只是使用者點「重試」時，前端重新載入整頁，因為 service worker 仍然沒有確認支援帳號資料隔離，前端再讀一次帳號資料也無法開始。

這一節的其他部分不變。

#### 前端

IndexedDB 與 service worker cache 不再寫成離線讀取用的資料。以「前端新增、修改或刪除資料時都要連上後端」開始的那一項改成：

- 前端新增、修改或刪除資料時都要連上後端。IndexedDB 讓前端只向後端讀取有變動的交易紀錄與歷史收盤指數（見這一節的第一項）；service worker 的 API cache 對 `frontend/src/utils/cache.ts` 的 `API_CACHE_PATHS` 列出的 API 先向後端讀取，request 因連線失敗結束，或後端（大盤指數以外的 API）超過 3 秒才回應時，改用上次的回應，例如 REC-R19 的現金股利紀錄與 MKT-R13 的大盤指數。兩者都不是為了讓 Taigu 離線可用：沒有網路時畫面依 ACCT-R18 顯示，所以使用者不會在沒有網路時修改資料，也就不會跟後端上的資料衝突。

  > 設計理由：做了 ACCT-R18 之後仍保留 service worker 的 API cache，因為前端讀到帳號資料之後，後端仍可能回應太慢，前端也可能連不上後端，這時 API cache 讓前端先顯示上次存下的現金股利紀錄（REC-R19），大盤指數也依 MKT-R13 顯示上次的行情。完整討論見 [0013](../plans/archive/0013-offline-screen.md)。

這一節的其他項目不變。

#### 分頁儲存與版本相容性

實測紀錄保留原本的結果，註明這是做 ACCT-R18 之前的結果。以「帳號 A 的 API 回應延遲 5 秒才完成時」開始的那一項改成：

- 帳號 A 的 API 回應延遲 5 秒才完成時，登入版本改變後不會把資料寫回帳號 B 使用的 API cache。IndexedDB、舊 API cache、最近點選股票與舊返回網址都會清除；帳號 B 離線時沒有讀到帳號 A 的資料。這項檢查以固定的成功登入回應與測試帳號 cookie 代替 Google 授權。這是做 ACCT-R18 之前的結果，做了 ACCT-R18 之後，沒有網路時開啟不會畫出頁面。

這一節的其他部分不變。

#### Service Worker 的更新

## 決策

### 連不上後端時要不要讓使用者看瀏覽器裡存下的資料

- 選項：一、開啟時畫出頁面，顯示 IndexedDB 與 service worker cache 裡的資料，並在頁面上提示目前離線；二、停在讀取畫面，說明連不上的原因。
- 結論：選二。Taigu 的數字是投資判斷的依據，開啟時畫面上沒有任何剛取得的數字，舊的價格與損益加上提示仍會被當成目前的數字。IndexedDB 與 API cache 原本的目的就是減少讀取量與加快顯示，不是離線使用（見 architecture.md 的「前端」）。
- 併入：account.md#ACCT-R18

### 使用中途沒有網路時怎麼顯示

- 選項：一、像開啟時一樣擋住整個畫面，恢復網路後拿掉；二、浮在頁面上、不改變版面的提示；三、不顯示，只靠各頁的更新失敗提示。
- 結論：選二。畫面上的資料在斷線前是最新的，擋住畫面的話，使用者就看不到正在看的內容，在隧道或電梯裡畫面還會反覆被擋住；前端擋住畫面時也得另外處理返回鍵、擋住期間的重試與瀏覽器誤報。選三時，持股價格（HOLD-R5）更新失敗沒有任何提示，使用者看不出資料已經停止更新。
- 併入：account.md#ACCT-R18

### 使用中途什麼時候顯示提示

- 選項：一、只在瀏覽器回報沒有網路時顯示；二、瀏覽器回報有網路、但 request 連續失敗時也顯示。
- 結論：選一，並在沒有網路滿 3 秒時才顯示。瀏覽器回報有網路時，單一 request 失敗不能證明連不上後端，選二要依失敗次數或時間猜測；3 秒讓訊號短暫中斷時畫面不閃動。
- 併入：account.md#ACCT-R18

### 恢復網路後更新行情

- 選項：一、等下一次定時更新；二、恢復網路時立刻重新抓，失敗就在 10 秒內再試；三、恢復網路 2 秒後重新抓一次。
- 取捨：選三之後，2 秒後那次仍然失敗的話，要等下一次定時更新，或使用者在各頁點重試。
- 結論：選三。Free 方案的更新間隔是 10 分鐘，選一的話，出隧道之後最久要看 10 分鐘斷線前的價格。選二的再試期間，每次失敗都會觸發 STOCK-R3、FAV-R12 與 MKT-R13 的更新失敗提示，要替這三條需求各加例外；等 2 秒讓網路先通，只抓一次，就不必改這三條需求。
- 併入：account.md#ACCT-R18

### 開啟時讀取帳號資料要等多久

- 選項：一、一直等到瀏覽器放棄連線；二、設一個逾時。
- 結論：選二，每次嘗試從開始讀取帳號資料起算 10 秒，涵蓋更新 access token 與重送 request 的整段。連上沒有對外網路的 Wi-Fi 時，request 可能一分鐘以上都沒有結果，畫面會一直轉圈；10 秒比手機網路正常讀取帳號資料的時間長很多。逾時只換畫面、不中止 request，之後讀到帳號資料就畫出頁面（不中止的原因見「做法要點」）。
- 併入：無

### 自動開始的嘗試在 10 秒內再試

- 選項：一、第一個 request 連不上後端就顯示「無法連上 Taigu」；二、10 秒內自動再試。
- 取捨：選二之後，後端真的停機時，使用者要看 10 秒轉圈的讀取畫面才看到原因。
- 結論：選二。解鎖手機或剛恢復網路時，瀏覽器常比網路真的通了更早回報有網路，選一會讓使用者經常看到「無法連上 Taigu」並自己點「重試」。點「重試」開始的嘗試不自動再試，讓使用者看得到這次重試的結果。
- 併入：account.md#ACCT-R18

### 開啟時後端回 401 以外的錯誤要怎麼顯示

- 選項：一、照現在的做法畫出頁面，頁面掛載時再讀一次帳號資料；二、跟連不上後端一樣顯示「無法連上 Taigu」。
- 結論：選二。讀不到帳號資料時，頁面也讀不到其他資料，畫出來只會是沒有資料的頁面。
- 併入：無

### 保留 Service Worker 的 API Cache

- 選項：一、移除 API cache 與 API cache 的帳號隔離機制；二、保留。
- 結論：選二。API cache 讓後端超過 3 秒才回應時先顯示上次的現金股利紀錄（REC-R19），也讓讀到帳號資料之後才連不上後端時，大盤指數仍顯示上次的行情（MKT-R13）。這兩種情況在做了 ACCT-R18 之後仍會發生。
- 併入：architecture.md#前端

## 做法要點

- 前端用瀏覽器的 `navigator.onLine` 與 `online`、`offline` 事件判斷沒有網路。`navigator.onLine` 是 `false` 時通常沒有網路，但可能誤報（所以 ACCT-R18 的「重試」不看它），是 `true` 時不代表連得上後端，所以連不上後端只由 request 的結果判斷。
- 切回 Taigu 或從 bfcache 還原頁面時，瀏覽器可能沒送出 `online`、`offline` 事件，所以 ACCT-R18 定義的「瀏覽器的回報」也包括這時當下的 `navigator.onLine`。實作時要在 iOS Safari 安裝的 PWA、Android Chrome 與桌面 Chrome 實測開啟、使用中途斷線、切回與解鎖手機時的事件與 `navigator.onLine`，記到 `architecture.md`。
- ACCT-R18 的 10 秒到了時，前端不中止進行中的 request，因為前端中止更新 access token 的 request 時，後端可能已經換發新的 refresh token，瀏覽器卻沒拿到，前端之後送出舊的 refresh token 時，後端會依 ACCT-R6 結束整次登入。新的嘗試如果也要更新 access token，前端照 ACCT-R6 的跨分頁協調等前一次更新結束，不另外送出舊的 refresh token。
- 在 prod，前端與後端在不同網域，後端經過 Cloudflare。後端停機時 Cloudflare 或 Nginx 回的錯誤頁可能沒有 CORS header，瀏覽器會讓 fetch 以連線失敗結束，前端就照 ACCT-R18 自動再試；在 dev 只停掉 `api-server` 時，前端讀得到 502，會照 ACCT-R18.5 立刻顯示「無法連上 Taigu」。要達成的結果是 prod 部署時後端重啟或後端停機時，前端跟連線失敗時一樣自動再試；實作時實測並記到 `architecture.md`，手動檢查用停掉 reverse proxy 的方式。
- 更新 access token 的 request 一直沒有結果時（例如連著沒有對外網路的 Wi-Fi），之後的嘗試都要等它結束。要達成的結果是網路正常之後，使用者點「重試」，前端在幾秒內畫出頁面，不會一直等那個卡住的 request；實作時實測瀏覽器換網路時會不會中斷卡住的連線，記到 `architecture.md`。
- 瀏覽器清掉 service worker 與 precache 時（例如 Safari 清除網站資料），使用者沒有網路時開啟 Taigu，會看到瀏覽器自己的離線頁面，ACCT-R18 的畫面不會出現。實作時在 `architecture.md` 記下 ACCT-R18 的畫面要靠 service worker 與 precache 才會出現。
- ACCT-R18 的讀取畫面就是 `LoadingScreen`，由 layout route 的 loader（`requireLogin`）與 `LoadingScreen` 負責。使用中途的提示是 `role="status"` 的提示，出現時不移動焦點。`LoadingScreen` 的層級高於視窗，所以頁面顯示讀取畫面時，前端要另外把提示疊在 `LoadingScreen` 上面。要做到不蓋住使用者正在輸入的欄位，建議欄位有焦點時，前端先收起提示，因為鍵盤開著時，iOS 會把固定在底部的元素帶到鍵盤上方（見 architecture.md 的實測）。
- 實作 PR 要在 `architecture.md` 的功能與程式碼對照表「帳號」那一列，加上 ACCT-R18 的元件。
- 隱私權政策的「個人資料之保存期間」裡，以「本網站會在您的瀏覽器保存部分帳號資料」開始的那一段改成下面這段，並把「最後更新日期」改成實作 PR 合併的日期：

  本網站會在您的瀏覽器保存部分帳號資料，以減少每次開啟本網站時需要下載的資料。登出或確認登入失效時，會清除這些本機資料。

- 改寫的情境裡，`tests/manual/` 已有的段落要照新的前提更新步驟，用停掉本機的 reverse proxy 這類方式讓前端連不上後端，不要用 DevTools 的 Offline，因為 DevTools 的 Offline 會讓瀏覽器回報沒有網路，那是 ACCT-R18 的「沒有網路」，不是「連不上後端」。
- 實作 PR 要從 `roadmap.md` 的「已知問題」移除這個 plan 解決的問題：「行情與重大消息修正」裡「離線開啟儀表板時，大盤指數的卡片一直顯示『讀取行情中』」那一項，以及「介面回饋與導覽修正」裡交易紀錄那一項的「或離線開啟時」。交易紀錄載入失敗時顯示成沒有資料的問題仍然存在，那一項的其他內容保留。
