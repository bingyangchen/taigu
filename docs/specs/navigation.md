# 前台導覽

前台依版面（見 ui-guidelines.md 的「版面」）切換導覽：窄版用底部導覽列，寬版用側邊欄。可用寬度至少 960px 時，使用者可以把側邊欄收合成圖示列，前端保留使用者在目前瀏覽器選擇的收合狀態。

## 需求

### NAV-R1 側邊欄的收合與固定位置

在 NAV-R2 列出的頁面，寬版且可用寬度至少 960px 時，側邊欄預設展開，寬度為 230px。使用者可以用側邊欄頂端的按鈕收合或展開側邊欄；收合時寬度為 64px，只顯示圖示，所有導覽與操作仍可使用，圖示也有 screen reader 可讀的名稱，滑鼠移入或鍵盤焦點停留時會顯示名稱 tooltip。按鈕能以鍵盤操作，並以 `aria-expanded` 表示目前狀態。

前端把收合狀態存在目前的瀏覽器，使用者在同一個瀏覽器切換前台頁面或重新載入後，側邊欄維持原狀態。瀏覽器沒有收合紀錄時，側邊欄預設展開；瀏覽器無法存取儲存空間時，收合操作仍在目前頁面有效，重新載入後側邊欄預設展開。

寬版的主內容捲動時，側邊欄固定在視窗左側，不隨主內容上下移動。側邊欄內容超出可用高度時，使用者可以獨立捲動側邊欄。

窄版，或寬版且可用寬度小於 960px 時，導覽依 NAV-R2，不顯示收合按鈕，前端也不改寫收合狀態。

- NAV-R1.1 第一次開啟桌面前台
  - 前提：使用者在這個瀏覽器沒有前台側邊欄的收合紀錄。
  - 動作：以 1280px 寬的視窗開啟儀表板 `/`。
  - 結果：側邊欄寬度是 230px，導覽文字與操作名稱都顯示，側邊欄有收合按鈕。
- NAV-R1.2 收合與展開側邊欄
  - 前提：使用者以至少 960px 寬的視窗開啟前台頁面，側邊欄已展開。
  - 動作：點收合按鈕，再點展開按鈕。
  - 結果：收合後側邊欄寬度是 64px，只顯示圖示，導覽與操作仍可使用，指到圖示或以鍵盤移到圖示時會顯示名稱；再次點按鈕後側邊欄恢復 230px 與所有文字。
- NAV-R1.3 用鍵盤收合與展開
  - 前提：使用者以至少 960px 寬的視窗開啟前台頁面，鍵盤焦點停在側邊欄的收合按鈕。
  - 動作：按 Enter 或 Space，再按一次按鈕。
  - 結果：每次操作都切換側邊欄狀態，按鈕的 `aria-expanded` 與側邊欄狀態一致，焦點清楚可見。
- NAV-R1.4 切頁與重新載入後保留狀態
  - 前提：使用者在同一個瀏覽器把側邊欄收合。
  - 動作：換到市場頁 `/market`，再重新載入頁面。
  - 結果：切頁與重新載入後，側邊欄都維持收合。
- NAV-R1.5 捲動主內容時固定側邊欄
  - 前提：使用者以至少 960px 寬的視窗開啟內容超過一個視窗高度的頁面，側邊欄已展開。
  - 動作：用滑鼠滾輪或觸控板捲動主內容。
  - 結果：主內容上下捲動，側邊欄維持在視窗左側原位；側邊欄內容超出可用高度時，捲動側邊欄不會帶動主內容。
- NAV-R1.6 窄版的導覽不受收合狀態影響
  - 前提：使用者已在同一個瀏覽器收合側邊欄，以 390 × 844 的可用畫面開啟前台。
  - 動作：開啟儀表板 `/`，再把可用畫面改成 1280 × 800。
  - 結果：390 × 844 時畫面顯示底部導覽列，沒有側邊欄與收合按鈕；改成 1280 × 800 後，側邊欄是收合的。
- NAV-R1.7 收合功能的最小可用寬度
  - 前提：使用者在可用寬度至少 960px、可用高度至少 480px 的視窗展開側邊欄。
  - 動作：把可用寬度縮到 959px，再拉回 960px。
  - 結果：959px 時側邊欄依 NAV-R2 收合成 64px 的圖示列，沒有收合按鈕；拉回 960px 時，側邊欄恢復展開，頂端有收合按鈕。
- NAV-R1.8 瀏覽器無法儲存收合狀態
  - 前提：瀏覽器無法存取前台側邊欄的儲存空間，使用者開啟寬度至少 960px 的前台頁面。
  - 動作：收合側邊欄，再重新載入頁面。
  - 結果：收合操作在重新載入前有效，重新載入後側邊欄預設展開。

> 設計理由：同一瀏覽器重新開啟前台時沿用側邊欄狀態，因為這個偏好屬於瀏覽器，不需要同步到使用者的其他裝置；瀏覽器無法儲存時仍保留目前頁面的操作能力。完整討論見 [0007](../plans/archive/0007-frontend-sidebar-collapse.md)。

### NAV-R2 依版面切換導覽

儀表板、市場頁、歷史紀錄頁、買賣計畫頁、收益分析頁、手續費頁、大盤指數頁與個股詳情頁，依版面（見 ui-guidelines.md 的「版面」）顯示導覽：

- 窄版：顯示底部導覽列，不顯示側邊欄。
- 寬版且可用寬度小於 960px：側邊欄收合成 64px 寬、只有圖示的一列，樣子與操作跟 NAV-R1 收合時相同，不顯示底部導覽列。
- 寬版且可用寬度至少 960px：側邊欄依 NAV-R1。

- NAV-R2.1 手機直立
  - 前提：使用者以 390 × 844 的可用畫面開啟前台。
  - 動作：開啟儀表板 `/`。
  - 結果：畫面顯示底部導覽列，沒有側邊欄。
- NAV-R2.2 平板直立
  - 前提：使用者以 768 × 1024 的可用畫面開啟前台，這個瀏覽器沒有側邊欄的收合紀錄。
  - 動作：開啟儀表板 `/`。
  - 結果：側邊欄寬度是 64px，只顯示圖示，沒有收合按鈕，畫面也沒有底部導覽列。
- NAV-R2.3 手機橫放
  - 前提：使用者以 844 × 390 的可用畫面開啟前台。
  - 動作：開啟儀表板 `/`。
  - 結果：畫面顯示底部導覽列，沒有側邊欄。
- NAV-R2.4 寬度跨過 600px
  - 前提：使用者以 1280 × 800 的可用畫面開啟儀表板 `/`。
  - 動作：把可用寬度縮到 599px，再拉回 600px。
  - 結果：599px 時畫面顯示底部導覽列，沒有側邊欄；600px 時畫面改成 64px 的圖示列，沒有底部導覽列。

> 設計理由：寬版且可用寬度小於 960px 時，側邊欄只顯示圖示，偏離 ui-guidelines.md「主導覽有可見文字」的預設，因為這一列跟可用寬度至少 960px 時使用者收合的圖示列相同，所以視窗寬度跨過 960px 時，導覽的圖示與位置都不變；而且這些圖示跟底部導覽列與展開的側邊欄用的是同一組，使用者在其他寬度可以看到這些圖示的名稱。不採用 Material Design 3 那種圖示下方附名稱、寬約 80px 的 navigation rail，因為那樣導覽會在三種樣子之間切換。這段寬度也不展開成 230px 的側邊欄，因為可用寬度是 600px 時，內容只剩 370px，比手機直立還窄。完整討論見 [0012](../plans/archive/0012-width-based-layout.md)。
