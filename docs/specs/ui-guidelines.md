# 介面與文案規範

本文件定義 Taigu 的介面與文案要遵守的規則，分為前台與後台共通的規則，以及各自的規則。產品定位與術語見 `product.md`，各能力的資料定義、計算規則與具體行為見該能力的 spec；畫面的設計流程見 `product-designer` skill。

現有的介面不符合本文件規則的地方，依 `sdd` skill 分類處理。

## 規則的適用方式

- **必須**：資料語意、可讀性、可操作性與操作安全的要求，各畫面都要遵守；需要改變這類規則時，先提議修改本文件。
- **預設**：設計時優先採用的做法。需要偏離預設時，提出具體原因與取捨，依 `sdd` skill 的流程確認，並在該能力的 spec 記錄例外。
- 前台與後台分別遵守各自章節，不能直接把前台的用途字級、資訊密度或導覽套到後台；字級與間距的 scale 則是前後台共用。後台使用共用元件時，元件的字級固定為前台寬版的值。

## 共通規則

### 語言與語氣

- **必須**：介面使用台灣的繁體中文。
- **必須**：同一個概念維持同一個用詞，並使用 `product.md` 術語表與各能力 spec 裡的名稱。
- **必須**：文案準確交代功能、資料與操作後果。
- **必須**：文案不承諾投資收益，也不使用投資建議口吻。
- **預設**：日常操作、資料說明與錯誤提示的文案務實、簡潔、友善、精確。

### 文案

錯誤與完成提示見「回饋」，破壞性操作的文案見「操作確認」。

- **預設**：用「你」稱呼使用者，不過法律頁面用「您」。
- **預設**：中文與英文字母或數字之間空一個半形空格。
- **預設**：中文句子使用全形標點。
- **預設**：按下去會新增、修改或刪除內容，或改變帳號狀態的按鈕，寫出動作與對象，例如「新增交易紀錄」「刪除折讓紀錄」，避免只寫「確定」「送出」；動詞本身已經說明對象時，例如「登出」，不用另外寫對象。
- **預設**：只關閉視窗或離開目前畫面、不改變任何內容的按鈕，例如「取消」「關閉」，可以只寫動作。

  > 設計理由：寫出對象是為了讓使用者不讀標題，也知道按下去會改變什麼，這只對會改變內容的按鈕有意義。「取消」「關閉」按錯也沒有損失，所有介面都這樣寫；寫成「取消刪除」只讓按鈕變長，手機上同一排的兩個按鈕更擠，在中文裡還可能被讀成撤回刪除。
- **必須**：保留使用者做決定需要的資訊，例如付款金額、續訂日期與刪除後果。

### Design Token、共用元件與圖示

- **預設**：沿用系統字型，`font-family` 的設定以 `frontend/src/styles/tokens/_typography.scss` 為準。
- **預設**：顏色一律以 `frontend/src/styles/` 的用途 token 為來源。
- **預設**：多個畫面共用的字級、間距、圓角、陰影、動畫、疊放層級、版面尺寸與斷點，以 `frontend/src/styles/` 的 token 為來源。
- **預設**：只有一個畫面或元件用到的尺寸與動畫，寫在那個畫面或元件自己的檔案；只有後台用到的值，寫在 `frontend/src/pages/Admin/`。
- **預設**：字級、間距與圓角使用 scale 上的值。有理由使用其他值時，寫成元件裡的 Sass 變數，並以註解說明理由。
- **預設**：同類元件沿用共用樣式。
- **預設**：使用 `frontend/src/components/` 的共用元件與 `frontend/src/icons/` 的圖示。
- **預設**：同一個功能在各處使用同一個圖示。
- **預設**：用於比較的數字欄位靠右對齊。
- **預設**：元素依視覺對齊（optical alignment）調整位置，不只看框的邊界是否對齊，例如沒有底色或邊框的文字跟有圓角的元件對齊同一側時，往內縮一點，因為圓角讓元件看起來比它的框更往內縮。
- **預設**：欄位裡的數字與會原地更新的數字使用 `font-variant-numeric: tabular-nums`。
- **預設**：金額與較大的數量加上千分位符號，例如 1,234,567；股票代號、日期這類不是數量的數字不加千分位符號。

### 可讀性與操作

- **必須**：文字與背景的對比符合「文字對比」一節的下限，文字本身的顏色不能是半透明的，也不能用 `opacity` 讓文字變淡。不過「文字對比」表裡的裝飾文字不受這兩項限制。
- **必須**：資訊不能只靠顏色區分，另以文字、符號或圖示交代意義。
- **必須**：主要按鈕的可點擊範圍至少為 44×44px；次要圖示操作在僅使用滑鼠的環境可為 32×32px，支援觸控的環境仍至少為 44×44px。
- **必須**：互動元件能用鍵盤操作；不過圖表上用 tooltip 查看單一資料點的數值時，可以只支援游標與觸控。
- **必須**：焦點位置清楚可見。
- **必須**：任何操作都不能只在滑鼠移入時才能使用；不過圖表上用 tooltip 查看單一資料點的數值時不在此限。
- **必須**：支援使用者用瀏覽器的設定放大文字與頁面，放大後主要資訊仍可閱讀，操作仍可使用。
- **必須**：前台與後台都用 viewport 的 `user-scalable=0` 關閉雙指縮放整個畫面。

  > 設計理由：不提供雙指縮放整個畫面，因為原生 App 也不能用雙指放大整個畫面，而 Taigu 的網頁與 PWA 照原生 App 的操作方式設計。需要放大的使用者仍可以用瀏覽器的設定放大文字與頁面。完整討論見 [0012](../plans/archive/0012-width-based-layout.md)。
- **必須**：瀏覽器不理會 `user-scalable=0`、仍讓使用者雙指縮放時（例如 iOS 的 Safari），前台的版面不因此在窄版與寬版之間切換。
- **必須**：對話框開啟後，焦點留在對話框內；對話框關閉後，焦點回到合理的觸發位置。
- **必須**：使用者開啟「減少動態效果」設定時，裝飾動畫改用靜態呈現，非必要轉場改為立即切換，載入狀態仍要看得出來。
- **預設**：供查閱的資料文字可以選取與複製，不過拖曳或手勢區域可以依操作需要停用文字選取。

### 文字對比

對比用 WCAG 2 的對比比值計算，下限依文字的用途與尺寸決定。

背景依使用者實際看到的顏色計算，蓋在文字上的遮罩要算進去，對比的比值不四捨五入。不過前台頁面背景的淡漸層以白色計算；半透明的背景不論疊在什麼底色或內容上，都以它疊在白色上的顏色計算。

> 設計理由：淡漸層與半透明的背景以白色計算，因為把淡漸層的顏色算進去時，所有可能放在漸層上的文字都要以漸層最深的顏色計算，藍字、按鈕的藍底與次要文字都得用偏深的顏色；半透明的背景不把底下的內容算進去，則讓按鈕與控制項的灰底、毛玻璃這類半透明的背景能帶上底下漸層的顏色，融進每一種底色。文字本身仍然不能是半透明的，因為半透明文字的實際顏色取決於底下的內容，文字的顏色 token 就保證不了對比。

用途依這段資訊在那個畫面上、當下的重要程度判斷，不看它用什麼元件顯示。停用樣式只用來表達控制項現在不能使用，本身不會讓文字的對比下限降低；停用中按鈕的文字算提示，是因為按鈕當下不能用，它的文字變得不重要。

| 用途 | 意思 | 例子 |
| --- | --- | --- |
| 主要 | 使用者理解畫面或進行操作時要讀的資訊 | 正文、清單與表格的資料、表單欄位的值、可以按的按鈕的文字 |
| 次要 | 說明主要資訊的資訊 | 欄名、日期、單位、說明文字 |
| 提示 | 當下比次要更不重要的資訊 | 已有標籤、圖示、視窗標題或段落標題說明用途的輸入框的 placeholder、停用中按鈕的文字 |
| 裝飾 | 不帶資訊、使用者不需要讀的文字，不受對比限制 | 浮水印這類文字 |

被視窗或 bottom sheet 的遮罩蓋住、當下不能操作的內容，不受對比下限限制。

尺寸依字級分段，字重 600 與 700 的文字往上算一段，例如 20px 的 700 算大字。字級以使用者實際看到的 CSS px 計算，包括使用者在瀏覽器放大文字之後的大小；落在兩段之間的值，例如隨寬度縮放到 17.6px 的標題，算較小的那一段：

| 尺寸 | 字級 |
| --- | --- |
| 小字 | 12px 以下 |
| 內文 | 14 到 16px |
| 中字 | 18 到 20px |
| 大字 | 24px 以上 |

| 用途＼尺寸 | 小字 | 內文 | 中字 | 大字 |
| --- | ---: | ---: | ---: | ---: |
| 主要 | 4:1 | 4:1 | 4:1 | 3:1 |
| 次要 | 4:1 | 3:1 | 3:1 | 3:1 |
| 提示 | 2:1 | 2:1 | 2:1 | 2:1 |

> 設計理由：對比用 WCAG 2 的比值計算，不用 APCA，因為 APCA 還不是正式標準、能用的工具也少，而 Taigu 只有淺色主題，WCAG 2 在深色背景上算不準的問題不會發生。下限不直接採用 WCAG 2.2 AA 的「一般文字」與「大字」兩檔，因為這兩檔不分字級與字重，而且例外依元件的狀態決定，例如停用中的輸入框如果顯示使用者需要讀的值，這個值就會落進停用元件的例外。所以用途依資訊的重要程度判斷，跟元件與狀態無關。字重 600 與 700 往上算一段，因為中文字型在 macOS 與 Windows 上把 600 與 700 顯示成同一種粗細。表裡只規定下限、不規定上限，因為主要與次要文字之間的層次已經由顏色 token 決定。完整討論見 [0011](../plans/archive/0011-design-system.md)。

### 文字與圖示操作

- **預設**：主要操作與主導覽有可見文字。
- **預設**：返回、關閉等通用控制項與列內次要操作可以只用圖示。
- **必須**：純圖示操作具有 screen reader 讀得到的名稱，並在滑鼠移入或鍵盤焦點停留時以 tooltip 顯示這個名稱。

### 資料語意與狀態

- **必須**：數值是零、缺值、不適用還是尚未完成，依各能力的 spec 判定，畫面不能把其中一種顯示成另一種。
- **必須**：範例資料明確標示為示意，與使用者的實際資料區分。
- **必須**：資料的日期、期間或更新狀態影響解讀時，清楚標示適用範圍。
- **必須**：資料取得時間與來源資料時間使用不同標籤。
- **必須**：區分首次使用、查詢沒有符合的結果與資料取得失敗。

### 回饋

#### 載入與查詢

以下查詢規則適用於同一個帳號內切換查詢條件；換成其他帳號時，帳號之間的資料隔離見 `account.md`。

- **預設**：首次載入且沒有既有資料時使用 skeleton，保留與內容相符的版面空間。
- **預設**：同一條件的背景更新保留既有內容，失敗時明確提示目前仍是舊資料。
- **必須**：切換查詢條件後仍保留舊結果時，控制項立即反映新選擇，結果區持續標示舊結果的適用條件與更新狀態。
- **預設**：切換查詢條件後，依查詢的進度處理：
  - 查詢發出時，結果區立即標示更新中。
  - 查詢超過 200ms 尚未完成時，結果區顯示 spinner。
  - 查詢超過 2 秒尚未完成時，結果區顯示「仍在查詢」並提供「取消套用」入口。
  - 查詢成功時，立即呈現結果。
  - 查詢失敗或逾時時，保留新選擇，並提供錯誤提示與重試入口。
  - 使用者按「取消套用」時，恢復上次成功的條件與結果。
- **必須**：較早發出的查詢回應，不能覆蓋使用者最新選擇的條件所查到的結果。
- **必須**：已取消或已逾時的查詢，回應不再套用。

#### 送出中的按鈕

- **預設**：按下會寫入資料、改變登入狀態，或載入下一批資料的按鈕之後、等待後端回應的期間，按鈕的文字或圖示換成 loading 圖示。不過畫面先套用結果、失敗時再恢復的操作，照它的 spec 處理。
- **必須**：按鈕顯示 loading 圖示時，screen reader 仍讀得到按鈕原本的名稱。

#### 錯誤與完成

- **預設**：錯誤提示留在受影響的欄位、區塊或頁面，交代原因與修正或重試方式，直到問題解決或使用者開始下一次操作。
- **預設**：原處已有完整的錯誤提示時，不再重複顯示 toast。
- **預設**：表單送出後的欄位驗證失敗，依表單順序將焦點移到第一個錯誤欄位，各錯誤欄位旁保留錯誤提示。
- **必須**：背景更新失敗不移動使用者目前的焦點。
- **預設**：簡短的成功 toast 停留 5 秒，可提前關閉；滑鼠移入或鍵盤焦點停留時暫停自動消失。
- **預設**：資料讀取與背景更新成功時，不顯示成功 toast。

### 操作確認

- **必須**：不可復原的資料刪除先確認，不過取消關注與可以再改回來的處理狀態切換直接執行。
- **必須**：使用者把已儲存且非空白的整段文字改成空白並送出時，先以確認視窗寫出清空的後果，請使用者確認；一般修改與原本空白的內容不額外確認。當作標題的單行欄位（例如手續費折讓的備註）不算整段文字。
- **預設**：確認視窗以問句為標題，寫出影響對象與後果，送出按鈕使用具體動作名稱。
- **必須**：能力提供清空整類資料或刪除帳號的操作時，使用者須輸入完整的動作名稱才能送出；單筆刪除與清空整段文字維持一般確認。

## 前台

### 版面

- **預設**：前台是親和、簡潔的投資記帳工具，總覽突出重要數字，清單較緊湊以方便比較。
- **預設**：淡漸層用於總覽與導覽，表格、圖表繪圖區及表單使用白色或近白色的中性底色。
- **預設**：依可用空間切換版面，不看裝置或 User-Agent。可用寬度小於 600px 或可用高度小於 480px 時是窄版，使用底部導覽列與窄版字級；其他情況是寬版，使用側邊欄與寬版字級。各頁內容另依需要調整排列。

  > 設計理由：窄版的寬度分界用 Material Design 3 的 compact 寬度（小於 600dp），因為手機直立時最寬約 440px，平板直立時最窄約 744px，600px 落在兩者之間，又有公開的出處。可用高度小於 480px（Material Design 3 的 compact 高度）也算窄版，因為手機橫放時寬度有 667 到 956px，高度卻只有 400px 左右，如果用寬版的編輯器視窗，鍵盤彈出後會蓋住大部分欄位。版面不看 User-Agent，因為 iPadOS 的 Safari 送出的是 Mac 的 User-Agent，Android 平板的 User-Agent 也不帶 `Mobile`，所以依 User-Agent 判斷時，平板會拿到桌面的版面；而且在桌面瀏覽器把視窗縮小時，版面也不會跟著改變。頁面內容只有窄版與寬版兩種版本，不替 600 到 959px 另做一種，因為寬版的編輯器視窗、對話框與卡片在平板直立的寬度放得下，側邊欄也已經有「新增」與「搜尋」，不需要加號選單。完整討論見 [0012](../plans/archive/0012-width-based-layout.md)。
- **預設**：觸控、滑鼠移入這類操作方式的差別，依 `hover` 與 `pointer` 這類 media query 回報的輸入能力判斷。
- **預設**：在新分頁還是同一個畫面開啟頁面，依 Taigu 是不是以 PWA 開啟判斷。
- **必須**：頁面本身不橫向捲動。
- **預設**：窄版的一般資料清單改為多行排列，需要跨欄比較的表格保留欄位結構，在自己的容器內橫向捲動。

### 卡片與分組

- **預設**：先以標題、對齊、間距與細分隔線組織內容。
- **預設**：同頁包含不同用途、需要各自閱讀的資訊區塊（例如市場行情、個人資產與近期交易）時，可以使用卡片。
- **預設**：同一摘要的個別數字、同類紀錄的各筆資料與同一表單的欄位，不逐項分成不同卡片。
- **預設**：同一組資料的圖表與明細，不因呈現形式不同就分成不同卡片。
- **預設**：卡片內使用平面排版，避免在卡片裡再放卡片。
- **預設**：改為單欄時移除一般卡片的容器外觀，以標題、間距與分隔線保留分組。
- **預設**：互斥選項（例如方案選擇）各自包含多項需要整組閱讀與選擇的資訊時，每個選項可以各自做成卡片，改為單欄時也可以保留卡片外觀，不過一般紀錄不會因為帶有編輯或刪除按鈕就適用這個例外。
- **預設**：一般卡片以底色、間距與必要細線建立層次。
- **預設**：陰影主要用於對話框、選單這類疊在頁面內容上方的元件。

### 字級與顏色

以下為預設字級，重要數字與標題可依資訊層級放大。

| 用途 | 寬版 | 窄版 |
| --- | ---: | ---: |
| 正文、表單輸入 | 16px | 16px |
| 操作按鈕（視窗、編輯頁與表單底部的送出、取消這一排） | 16px | 14px |
| 表格／清單資料、欄名 | 14px | 14px |
| 日期、股票代號與輔助文字 | 12px | 11px |
| 側邊欄的導覽文字 | 14px | 無 |
| 底部導覽列的導覽文字 | 無 | 11px |
| 圖表刻度 | 11px | 11px |

- **預設**：表格以外的字級在寬版與窄版相同；標題與頁面最重要的數字（例如儀表板的投入金額）可以隨視窗寬度縮放。

> 設計理由：窄版的操作按鈕與輔助文字比寬版小，讓手機的小螢幕放得下更多內容。用途字級跟版面在同一個分界切換，因為在 780px 或 960px 切換時，有一段寬度會出現一種版面配上另一種版面的字級，例如寬版的側邊欄配上窄版字級；也不依輸入方式（`pointer: coarse`）切換，因為縮窄桌面瀏覽器的視窗時，版面換成窄版，字級卻不會跟著換。表格以外的字級在每個寬度都一樣，因為以前各元件各自在 media query 裡縮小字級，同一種文字在不同頁面縮成不同的大小，切換點也各自不同，所以窄版要變多小，集中由用途字級與 `clamp()` 決定。完整討論見 [0011](../plans/archive/0011-design-system.md) 與 [0012](../plans/archive/0012-width-based-layout.md)。

- **預設**：藍色主要用於操作、選取狀態與圖表資料系列。
- **預設**：中性摘要數字以位置、字級與字重突出。
- **預設**：字重只用 400、500、600、700 四種。

### 漲跌

- **預設**：數值中的紅綠色限於漲跌、損益與報酬率，紅色代表上漲或獲利，綠色代表下跌或虧損，零值使用中性色。
- **預設**：一般股價、成本、投入金額、股數與單筆現金股利使用中性色。
- **預設**：行情漲跌搭配 ▲／▼，損益與報酬率搭配正負號。
- **必須**：錯誤或破壞性操作使用紅色時，搭配明確文字與圖示，讓使用者看得出這裡的紅色不代表行情上漲。

### 數字

- **預設**：數字依種類標示單位：
  - 金額摘要與交易紀錄的金額附貨幣符號或「元」。
  - 數量附「股」或「張」。
  - 百分比附 `%`。
  - 行情股價可以在欄名或區塊標題統一標示「元」。
  - 圖表由座標軸標示單位。
- **必須**：窄版重排後仍保留可見的單位標示。
- **預設**：數字依種類決定顯示的小數位數：
  - 股價與成交單價保留有效小數位，省略尾端的零。
  - 彙總金額四捨五入到整數。
  - 平均成本等計算出的每股金額最多顯示兩位小數，省略尾端的零。
  - 投資相關百分比固定顯示兩位小數。
- **必須**：顯示格式與計算、儲存精度分開，顯示值不用於後續計算，計算規則依各能力的 spec。
- **預設**：個別缺值或不適用的數字使用 `--`，原因放在鄰近說明或可操作的資訊入口；同一區域的原因可以集中說明，但不能只靠滑鼠移入查看。

### 引導、動態與回饋

- **預設**：新手引導搭配範例、圖解或插圖，以及開始操作的入口，說明服務用途與核心流程。
- **預設**：個別功能的引導保持簡短，符合當下任務。
- **預設**：歡迎頁與新手引導的文案可以更親切、帶有鼓勵語氣，日常功能的文案維持直接、精確。
- **預設**：日常資料、表單與清單的動態只用於操作回饋、狀態變化與必要轉場。
- **預設**：新手引導與品牌區域可以使用輕量裝飾動畫，也可以緩慢循環。
- **預設**：使用者主動新增、編輯或刪除資料成功後，顯示簡短的成功 toast。
- **必須**：操作受限時，說明限制種類、影響與適用的下一步；限制的內容依該能力的 spec。
