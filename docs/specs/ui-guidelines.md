# 介面與文案規範

每個畫面與每段介面文案都要遵守本文件的規則。這些規則描述 Taigu 想要的介面，`main` 上還沒符合規則的畫面，照 sdd skill 用 change 修正。設計畫面的流程寫在 `product-designer` skill。

## 語言與語氣

介面使用台灣的繁體中文。語氣務實、簡潔、友善、精確，不用行銷話術，也不用聽起來像投資建議的說法。

## Design token、共用元件與 Icon

顏色、斷點與版面尺寸都是 `frontend/src/_design_system.scss` 裡的 SCSS token，基本的字型寫在 `frontend/src/index.scss`，這兩個檔案以外不寫死這些數值。共用元件放在 `frontend/src/components/`，icon 放在 `frontend/src/icons/`。

## 配色

主要的顏色有藍 `#4c8bf5`、紅 `#d4493f`、綠 `#1aa260`、黃 `#fbbc05` 與深灰 `#444`，紅色與綠色的用法寫在下面的「漲跌」一節。灰色 `#888` 放在白底上的對比約是 3.5:1，低於內文需要的 4.5:1，所以只用在大字或次要的文字。

## 漲跌

紅色代表上漲或正數，綠色代表下跌或負數，跟美國的 app 相反。漲跌不能只靠顏色表示，要搭配 ▲／▼ 或 +／− 號。因為紅色已經代表上漲，在有價格資料的畫面上顯示錯誤或破壞性操作時，除了用紅色，還要加上 icon 與明確的文字。

## 數字

金額加上千分位（`toLocaleString()`）。數量、金額與百分比一律寫出單位（股、張、元、%），因為 1 張是 1,000 股。數字欄位靠右對齊，欄位裡的數字與會原地更新的數字使用 `font-variant-numeric: tabular-nums`。

## 版面

App 依裝置類型而不是視窗寬度選擇版面：`Util.isMobile` 檢查 user agent，行動裝置使用 `HeaderForMain` 與底部的 `Footer` 導覽列，桌面瀏覽器使用固定 230px 寬的 `MainSideBar`。兩種版面同樣重要，每個畫面都要為兩種版面設計；在各自的版面裡，每個畫面再用 `_design_system.scss` 的斷點，依視窗寬度調整內容。

頁面不會水平捲動，寬的表格在自己的容器裡捲動。行動裝置上的觸控目標至少要有 44×44px。

## 回饋

- 使用者需要等待處理結果時，畫面都要顯示載入狀態或 skeleton。
- 破壞性操作要先請使用者確認。
- Free 方案的額度擋下操作時，畫面顯示 `PlanUpsellModal`，寫出用完的是哪一種額度，以及 Standard 方案能解除哪些限制。

## 文案

- 用「你」稱呼使用者，只有法律頁面（隱私權政策、服務條款）用「您」。
- 中文與英文字母或數字之間空一個半形空格（「用 Google 帳號登入」「近 1 個月」），中文句子使用全形標點。
- 使用台灣券商 app 的用語（股、張、現股、除權息、殖利率、未實現損益），因為使用者已經在券商的 app 看過這些詞。
- 按鈕寫出動作與對象，例如「新增交易紀錄」，不寫「確定」。
- 破壞性操作的確認視窗用問句當標題（「刪除買賣計畫？」），在說明寫出後果（「刪除後，……」），送出按鈕再寫一次動作（「刪除買賣計畫」）。
- 文案保持簡短，但保留使用者做決定需要的資訊，例如付款前的金額與續訂日期，以及刪除後會失去哪些資料。
